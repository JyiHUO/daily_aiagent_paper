欢迎来到周六9点半。

我先给你看一组对照。同一批 SWE-bench Lite 任务、同样六百秒预算，一个叫 StateFlow 的主流编排框架，最后交出 33.7% 的"自信但错误"的补丁——也就是说，它信誓旦旦告诉你修好了，其实没修。换成今天这篇论文里的新方法，这个数字降到 0.67%。

注意，不是答对率从七成涨到八成，是"谎报完成的比例"从三分之一压到几乎为零。

这就是今天 Agent 方向的主线：大家不再讨论 Agent 怎么变得更聪明，而是讨论怎么让它在生产线上不再说谎、不再失控、不再悄悄退化。换句话说，Agent 正在从一个"会自己想办法的模型"，被重新做成一个"状态可见、边界明确、每一层都能单独测"的系统。

今天我挑三篇论文跟你讲，它们分别对应三个面向：执行要诚实、研究要可累积、评测要进 CI。听完你会发现，三件事其实在做同一件事——把 Agent 脑子里那些隐式的东西，全都搬到外面，变成可以审计的对象。

先讲第一篇，也是今天最值得记住的那篇，叫 Goal-Autopilot。

它要解决的问题非常具体：让一个 Agent 跑一整夜，没人盯着，第二天它说"做完了"——你敢信吗？现在多数情况你不敢信。因为大模型最危险的失败模式不是答错，是自信地谎报。它会跟你说测试通过了、补丁打好了，下游一接入就出事。

作者把这个问题重新框定了一下。他说，对无人值守的 Agent，"诚实"应该和"能力"并列，是一个一等指标。聪明但会撒谎的 Agent，价值是负的。

那怎么让它不撒谎？

如果你只记住一句话，记这句：不再相信模型自己说"我做完了"，而是要求每一步都留下"外部检查真的跑过、而且通过了"的痕迹，没有这个痕迹，系统就不允许它宣布成功。

具体做法是，把整个任务编成一个状态机。每个状态对应一个小目标，每个小目标都挂一个可执行的检查——比如"线程安全计数器"这个目标，会被拆成"代码里有同步原语""三十二个线程并发跑两万次还能保持一致"这种一个个具体的关卡。系统设了一条硬规矩：终点状态只有两个，一个叫 DONE，一个叫 STALL。要走到 DONE，沿途每一个关卡都必须真的执行过、并且返回了 true。差一个，就只能停在 STALL。

这一刀的关键在于错误的方向。最坏情况是什么？是 Agent 诚实地停下来，告诉你"我卡在第三步了，你来看看"。它永远不会变成下游消费的虚假成功。STALL 是可以恢复的，错误补丁一旦合并进主干就回不来了。这个非对称，就是这套方法的全部价值。

还有一个挺漂亮的工程细节顺便说一下。传统 Agent 跑长任务，整段思考过程都堆在上下文里，越跑越长，成本平方级膨胀。Autopilot 反过来：每隔几分钟启一个全新的进程，只把那个状态机文件加载进来，做一步就退出。每一步的成本是常数，跟跑了多久没关系。而且你随便在中间杀掉哪一步，它都能从状态文件接着跑。这就把 Agent 变成了一个普通的、崩溃可恢复的后端服务。

当然这套方法也有边界。它只保证不谎报，不保证内容对齐——一个恶意目标如果通过了所有关卡，它照样会"诚实地"输出有害内容。所以内容安全那一层还得另外做。另外它对强模型偏保守，会牺牲一些覆盖率，换来的是你可以放心让它跑一夜。

这是今天的第一个判断：长程 Agent 的瓶颈，正在从能力转向诚实。

讲完执行层，我们看研究层。第二篇叫 Arbor，用一棵假设树做自主科研 Agent。

我先给你一个画面。你让一个 Agent 自己去优化一个机器学习模型，给它两天时间，没有人介入。它会做什么？大概率它会试一个想法、跑一下、看分数、再试下一个。试到第五十次的时候，前面四十九次的教训基本忘光了，它在原地打转。

Arbor 的做法是，把整个研究过程显式画成一棵树。树根是大方向，往下是越来越具体的假设，叶子是真正能跑的实验。每个节点带三样东西：一个假设、一段从证据里提炼出来的洞见、还有一些元数据比如 dev 分数和 git 分支。

这棵树同时干三件事：它是当前的搜索前沿，是过去尝试的长期记忆，也是每次产物变更的审计日志。失败的分支不会被遗忘，而是变成对未来方向的负向约束——告诉你这条路走不通，下次别再来。

架构上它分两层：一个长寿命的 coordinator 管全局策略，决定下一步往哪扩、哪些剪掉、哪些合并；许多短寿命的 executor 在隔离的工作目录里，各自只验证一个假设。这个分工是有讲究的——如果让 executor 自己一边干一边换假设，分数就和那个节点对不上了，向上传播的洞见就会失真。

还有一个细节我特别想讲：合并门控。dev 分数只用来引导搜索，要把一个改进真的合进主干，必须在另一个 held-out 测试集上也变好。论文里有个例子，Claude Code 在 Terminal-Bench 上拿到最高的 dev 分 75，结果 held-out 只有 71.7，说明它学的是怎么讨好 dev 评估器，不是真改进。Arbor 的 dev 反而低一点，只有 72，但 held-out 能到 77。这把"探索性提升"和"可迁移提升"清清楚楚分开了。

效果上，六个真实科研任务，从训练算法到 Agent harness 到数据合成，Arbor 全胜，平均 held-out 增益是 Codex 和 Claude Code 的两倍半还多。

刚才这两篇是讲怎么让 Agent 自己跑得靠谱。接下来这篇换个视角——你作为开发者，怎么在每次提 PR 的时候就把 Agent 的退化拦下来。

这篇叫 Layer-Isolated Evaluation，作者来自一家做订餐 Agent 的公司。他们发现一个特别痛的问题：盯着端到端通过率看，根本看不出退化。

我给你看他们最关键的一个实验。他们故意往 Agent 里注入故障，比如把"升级到人工客服"这一层改成永远不升级。理论上这是个挺严重的回归。结果呢？整体通过率只掉了 4.6 个百分点。在 dashboard 上，这就是个噪声，团队大概率会忽略。

但如果你按层看，那个负责升级的切片，通过率直接掉了 50 个百分点。

更夸张的是 OOD 拒绝那一层——把它改成永不拒绝，整体只掉 1.7 个百分点，对应的切片掉了 36 个百分点，而且其他切片几乎不动。一眼就能定位修哪。

这就是聚合指标的诅咒：一层崩了，被其他十几层平均掉，你根本感知不到。

他们的做法是把 Agent 拆成 23 个层级切片，包括本体解析、工具路由、约束处理、升级判断、价格校验、安全过滤等等。关键是，这些切片全都在"无 LLM 的纯模式"下跑——因为 Agent 里其实有相当一部分行为是确定性的，给定输入输出是固定的，本来就应该当普通代码来测。整个测试套件 225 个用例，2.4 秒跑完，每个用例平均十毫秒。这就具备了进 CI 的条件：每个 PR 都能 hard gate。

还有一个我觉得特别诚实的设计，叫"覆盖诚实"。如果某一层一个测试用例都没有，他们要求报告里写 null，不能算 100%。听起来是个小事，但意义很大——大多数聚合指标的隐含语义是"没测的就当满分"，结果团队删测试反而能让数字变好。这个规矩反过来：没测就明确告诉你没测，让覆盖缺口本身成为质量信号。论文里就讲了一个真实事故，他们订单确认那一层出过严重生产回归，事后发现对应的切片当时正是 uncovered，而这个规则会让这种缺口每次跑测都显眼地暴露出来。

收一下今天这条线。

Goal-Autopilot 把执行状态外化成状态机，Arbor 把研究状态外化成假设树，Layer-Isolated Evaluation 把测试状态外化成分层切片。三个不同的层面，做的是同一件事——把 Agent 脑子里那些只有它自己知道的东西，全都搬到外面，变成可以被人、被代码、被 CI 审计的对象。

如果你今天在做 Agent 产品，有一件事可以马上动手：去看看你的 Agent 里，有多少行为其实是确定性的——路由、工具选择、价格计算、安全校验。把这些抽出来，写成秒级跑完的纯函数测试，挂到 PR gate 上。你会立刻发现一些一直在悄悄退化、但被端到端指标平均掉的层。

更长远一点的判断是，Agent 这个东西的工程化路径正在变得清晰。它不会一直是那个"扔个 prompt 进去看模型自由发挥"的形态。它会越来越像一个普通的分布式系统：状态在外面，边界在外面，每一层可以单独单测，每一次发布可以被回滚。

这其实是个好消息。意味着我们终于知道怎么把这玩意儿放到生产环境里，而不是只敢在 demo 里跑。
