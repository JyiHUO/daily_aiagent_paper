早上好，今天是 2026 年 04 月 22 日。这期 AI Agent 论文播报，主要覆盖 cs.AI、cs.CL、cs.LG、cs.MA、cs.RO、cs.SE、cs.HC 这些分类里最值得看的工作。

今天初筛后最集中的主题是 general_agent、embodied_agent、planning_reasoning，说明研究关注点继续从单轮回答能力转向更完整的执行链。

高优先级论文里，From Craft to Kernel: A Governance-First Execution Architecture and Semantic ISA for Agentic Computers 等工作都在强调 Agent 的系统边界，而不是只卷更大的底座模型。

从创新性和研究开拓性看，From Craft to Kernel: A Governance-First Execution Architecture and Semantic ISA for Agentic Computers、How Adversarial Environments Mislead Agentic AI? 代表了今天最值得后续继续追踪的切口。

先补一个今天特别值得懂的基础概念，叫做Planner 为什么重要。Planner 可以理解成 Agent 在真正动手前先安排'先做什么、后做什么、每一步依赖什么反馈'的那层机制。没有 planner，系统容易把任务做成一步一拍脑袋的局部反应；有了 planner，Agent 才能处理长任务、跨工具任务和需要中途修正的任务。很多 Agent 能力差异，最后都不是出在语言生成本身，而是出在计划层有没有把任务拆对、有没有给执行留回退空间。 今天的重点论文里，反复出现了评测、执行链安全、工具与环境交互这些问题，所以补这个概念最划算。

第 1 篇论文是《From Craft to Kernel: A Governance-First Execution Architecture and Semantic ISA for Agentic Computers》。它的主题是 agent_safety。为什么入选？Arbiter-K 提出了一种将 LLM 视为'概率处理单元'并用确定性符号内核封装的治理优先架构，定义了语义指令集架构（Semantic ISA）、安全上下文注册表、指令依赖图和运行时污点传播机制，在 Agent 运行时安全层面实现了从反应式补丁到体系结构级保障的范式转变，对 Agent 系统的生产化部署有重大启发。。这篇论文的背景是：当前主流 Agent 框架把 LLM 当作系统控制环的核心，安全仅靠文本级 guardrail 做事后过滤，实验显示原生防护对间接语义注入的拦截率不到 9%。问题根源在于概率推理与确定性执行之间缺少正式接口：模型输出是不透明的 token 流，系统无法做细粒度的权限校验和数据流审计。论文借鉴经典操作系统 ISA 的思路，提出在 Agent 运行时建立一层确定性符号内核来封装不可信的 LLM，把安全从'涌现行为'变成'架构属性'。。如果只记一个关键信号，我会记它的创新性分数是 93，研究开拓性分数是 95，说明它不仅有眼前价值，也可能影响后续 Agent 研究路线。

第 2 篇论文是《Scaling Test-Time Compute for Agentic Coding》。它的主题是 code_agent。为什么入选？这篇论文直接针对长程编码Agent的test-time scaling瓶颈，提出以紧凑轨迹摘要为核心表示，结合递归锦标赛投票(RTV)和并行蒸馏精炼(PDR)两种推理时扩展机制，在SWE-Bench Verified和Terminal-Bench v2.0上实现显著且一致的提升。对Agent系统的trajectory复用、经验选择和多轮推理架构设计有直接且深远的启发。。这篇论文的背景是：Test-time scaling（推理时扩展计算）在数学推理和单轮代码生成中效果显著，但长程编码Agent每次尝试会产生冗长、嘈杂的交互轨迹（包含文件读写、命令执行、错误恢复等），传统方法无法直接对这些长轨迹进行比较、排序或复用。原有方法如majority voting或简单的best-of-N选择在面对长horizon Agent轨迹时效果有限，因为原始轨迹中有用信号被大量低价值细节淹没。本文认为，长程Agent的推理时扩展本质上是一个表示(representation)、选择(selection)和复用(reuse)问题，值得关注是因为它为所有基于LLM的Agent系统提供了一个通用的推理时增强框架。。如果只记一个关键信号，我会记它的创新性分数是 85，研究开拓性分数是 90，说明它不仅有眼前价值，也可能影响后续 Agent 研究路线。

第 3 篇论文是《AutomationBench》。它的主题是 agent_eval。为什么入选？这是首个同时要求跨应用协调、自主 API 发现和业务策略遵循的 Agent 基准，来自 Zapier 真实工作流模式，前沿模型得分低于 10%，直接暴露当前 Agent 在企业级自动化中的能力瓶颈。。这篇论文的背景是：企业日常工作流常横跨 CRM、邮箱、日历、消息平台等多个应用，要求 Agent 自行找到正确的 API、遵守组织策略、在干扰数据中定位关键信息。现有 benchmark（WebArena、AppWorld、τ-bench 等）要么局限于单应用，要么不要求自主发现 API，要么缺少业务规则遵循维度。AutomationBench 由 Zapier 团队基于其平台真实客户工作流模式构建，覆盖 6 大业务领域、47 款应用、约 500 个 API 端点，是目前最接近企业真实自动化需求的 Agent 评测基准。。如果只记一个关键信号，我会记它的创新性分数是 80，研究开拓性分数是 90，说明它不仅有眼前价值，也可能影响后续 Agent 研究路线。

如果把今天的论文连起来看，一个明显变化是：大家越来越少把 Agent 当成单一模型能力问题，而是把它当成执行链、工具层、评测层和安全层共同构成的系统问题。

这意味着后续真正有开拓性的研究，往往不是再加一点 prompt 技巧，而是重新定义 Agent 应该如何被评测、如何被约束，以及如何在真实环境里更稳地工作。
