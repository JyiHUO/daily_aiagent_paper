欢迎来到周六9点半。

今天有一篇论文，直接把当下所有 Agent 框架的根基掀了一下。它问了一个挺刺耳的问题：我们费心费力写的那个 agent loop，那个 while 循环——它真的应该写在框架里吗？还是说，应该让模型自己写？

这就是今天要讲的第一件事，也是今天我想让你带走的主判断：Agent 的 runtime 正在被重新定义。编排权在往模型补全里下沉，而安全的关注点，正在从"prompt 怎么写"下沉到"数据怎么流"。

换句话说，过去我们做 Agent，重心是调 prompt、堆 harness、写各种工具调用模板。今天这一批论文合在一起告诉你：未来的重心，是把控制流交给模型、把安全交给数据流图、把训练环境当成一项基础设施工程来做。

我们先从那篇最有冲击力的论文讲起，叫 Self-Programmed Execution，缩写 SPE，来自哈佛医学院的 Luke O'Connor。

它的核心想法其实一句话就能讲完：让模型的输出本身，就是下一轮的编排程序。

我换个具体一点的方式说。你现在做一个 ReAct agent，框架里大概是这样：一个 while 循环，每轮里调用模型，把模型返回的 action 解析出来，执行工具，把结果拼回 conversation history，再进下一轮。这个 while 循环、这套上下文拼装策略，是你这个工程师写的，是固定的。

SPE 干的事情是：把这个 while 循环，也写进模型的输出里。

具体怎么实现？harness 退化成一个 Lisp 解释器，叫 Spell。模型每次返回的，不是一句话，而是一段代码。这段代码自己决定：要不要再调一次模型，调之前要保留哪些上下文，要不要先去读个文件，要不要把工具结果丢掉不进下一轮。框架完全不知道这是 ReAct 还是别的什么模式——一切都是模型生成的代码在驱动。

这里有个特别巧的工程细节，我觉得值得讲一下。

你想啊，如果模型每次输出的代码都把上一轮的代码作为前缀带过来，再 eval 一遍，那不就死循环了吗？工具调用也会重复执行。

Spell 的招数是：把会产生副作用的部分，比如调工具、发起下一轮 self-call，统一放在程序的最后一行，并且加上引号，让它只是一段数据。外层的 wrapper 只 eval 这"最后一行"。

下一轮，模型把新代码追加在这一行之后——于是上一轮的那个"最后一行"，自然就不再是最后一行了，自动降级成无害的字面字符串，还在上下文里供模型看，但不会再被执行。

副作用不会重放，控制流又能延续。这个设计真挺优雅的。

那效果怎么样？作者拿 GPT-5.4、Claude Opus、Kimi 这些前沿模型试了一下，没做任何专门训练，光靠 system prompt 和文档，模型就能上手这门小众 Lisp。在 Terminal-Bench 和 SWE-bench Lite 上，跟成熟的 Codex CLI 打成平手，但 token 消耗少了大概 4 倍。

为什么 token 少这么多？这就是 SPE 真正起作用的地方。

模型最爱用 Spell 干两件事：一是精细控制哪些工具结果进下一轮上下文。比如 ls、grep 这种输出一大坨的命令，它用一个叫 !peek 的语法包起来，看一眼就丢，不让这些垃圾占后续上下文。二是把多个工具调用串起来一次执行，不用每次都重新过一轮模型。

这两件事，正好是今天所有做 Agent 产品的人最头疼的——上下文管理。

不过论文也很坦诚地说了边界。模型现在会用 SPE 的，也就这两招。让它自己派子 Agent 干活？基本不会，作者观察到的少数尝试还都是有害的。理论上 SPE 能表达任何编排策略，但能表达不等于会表达。要让模型真正发挥这个范式的潜力，可能得专门为 Spell 训一版模型。

那这件事对做产品的人意味着什么？

我觉得最实在的启发是：以后做 Agent 平台，可能不需要再维护那么重的 agent loop 和 conversation history 了。提供一个能 eval 模型代码的沙箱，加几个 effect 命名空间，剩下的让模型自己写。这不是说今天就能上生产，但方向上，harness engineering 这个岗位，未来五年大概率要被模型吃掉一大块。

讲完这个范式级的变化，我们来看第二件事——既然 Agent 训练越来越重要，那训练环境从哪来？

苹果今天发了一篇 Weblica，专门解决 web agent 训练环境的问题。

为什么这件事难？你想训一个能在网上点点点的 agent，三条路。第一条是录离线轨迹做监督学习——但没有交互，模型学不到怎么应对意外。第二条是用 WebArena 这种手工模拟环境——但就那么几个域，覆盖太窄。第三条是直接上真网训练——超时、反爬、网站改版，三天两头给你掀桌子，不可复现。

Weblica 的解法分两条腿。

第一条腿叫 HTTP 缓存。简单说，就是给真实网站拍一张可交互的快照。

它先让一个 agent 把网站逛一遍，所有 HTTP 请求和响应全录下来。然后回放的时候，会发现有些参数每次都不一样——时间戳、session token 这种——这些就是噪声，把它们从 cache key 里剥掉。于是同一个 URL，在完全断网的情况下，也能稳定吐出当时录下的页面。

只有那些在断网回放下还能完成任务的会话，才会被收进训练集。这一招让他们从一个真实任务池里筛出了一万五千多个可复现的环境。

但缓存解决不了那种需要真改状态的任务，比如填表、加购物车。所以第二条腿就更狠了——直接让 Claude Code 当外包，按"我要练表单填写 + 这是越野摩托社区 + 用拟物风格"这种三维参数下单，生成一整个能跑的小网站，附带十来个不同难度的任务。最后量产了两千多个站、四万多个任务。

把这些环境全搬到本地、关掉浏览器动画之后，单步交互从一秒半压到一两百毫秒。RL 训练的瓶颈一直不是算法，是环境吞吐——这一下就解开了。最后训出来一个 8B 模型，在 Online-Mind2Web 上把同尺寸的开源 baseline 从 28.6% 提到 39.2%。

我觉得这篇论文真正的价值，是把"造可复现环境"这件事，正式抬到了一等公民的位置。如果你团队在做浏览器型 agent，与其在线上跟反爬斗智斗勇，不如花点功夫先把私有的训练沙盒建起来。HTTP 录制加易变参数自动剥离，是个能直接抄的基础设施模式。

当然也得说清楚边界：缓存搞不定登录态和强后端逻辑，合成网站和真实长尾网站之间也存在风格 gap，靠 LLM judge 打分还可能高估完成率。所以这套东西是训练加速器，不是真实评测的替代品。

好，第三件事，安全。

如果你最近在用 MCP——就是 Anthropic 那个让 LLM 调外部工具的协议——这一段你必须听一下。

MCP 推出 16 个月，服务器数量已经接近 6 万。但华中科技大学这篇论文揭出来的现实是：通用静态分析工具在 MCP 上基本是瞎的。CodeQL 在 32 个已确认 CVE 上只能找出 1 个。Semgrep 找到 8 个。专门做 MCP 的 MCPScan 也就 11 个。而他们这套叫 MCP-BiFlow 的工具，找出了 30 个，召回 93.8%。

更吓人的是后面那个数字：他们扫了 15,452 个真实开源 MCP 仓库，最后人工确认了 87 个服务器、118 条漏洞路径。其中 111 条是代码执行级别——也就是远程命令执行。

这些不是实验室构造的，是 GitHub 上正在跑的代码。

为什么通用工具会瞎？两个原因。

第一，MCP 没有 Flask 那种清晰的路由。一个工具往往藏在一个通用 handler 里，靠 name 字符串来分发。通用分析器看不到这层结构，就把所有工具糊成一团分析，要么误报炸裂，要么直接放过。

第二，也是更关键的——MCP 的安全问题是双向的。

传统 Web 安全只盯一条线：用户输入到危险函数。但 MCP 多了一条反向通路：工具的返回值会被 LLM 再读一遍，然后可能触发下一次工具调用。

举个真实的例子。有个 mcp-server-kubernetes，它有个工具能返回 pod 的 log。攻击者只要往 pod log 里写一段精心构造的内容，这段内容就会通过工具返回流给模型，模型读到之后被诱导，再去调一个危险工具。整条攻击链，根本没有传统意义上的"用户输入到 sink"，但它就是成立了。

所以这篇论文做的事情，是同时盯进口和出口。请求侧：参数从协议边界进来，到 exec、eval、fetch 这种 sink。返回侧：外部抓的内容，比如 HTTP response、文件、日志，怎么穿过协议边界回到模型。两端同时跑污点分析，再做交集。

最让我觉得讽刺的一个例子，是一个叫 mcp-server-text-editor 的工具。听名字像个只读的文本编辑器对吧？结果它的 path 参数只校验了"是不是绝对路径"，就直接拼进 execSync。攻击者塞一个带 shell 元字符的绝对路径，立刻就是任意命令执行。

对所有正在做 Agent 平台的团队，这件事的启发非常具体：你接入的 MCP 工具，入参和返回值，都得当成潜在攻击面。返回内容尤其要做隔离标记——不能让 LLM 把外部抓回来的字符串，当成可信指令二次消费。

能用 allowlist 的地方，别用黑名单自检。该用参数化查询的地方，别用字符串拼接。这些老掉牙的安全原则，在 MCP 这层得重新过一遍。

好，我们把今天的三件事收一下。

SPE 把控制流推进模型补全，让 Agent 框架变得更薄。Weblica 把网页环境量产成可复现的本地副本，让 RL 训练规模化。MCP-BiFlow 把协议安全做成静态分析工具，让数据流治理可执行。

这三件事看起来一个讲架构、一个讲数据、一个讲安全，但它们指向同一个判断：Agent 工程化的下一阶段，不再是调 prompt 和堆 harness，而是把 runtime、训练环境、协议边界都重新做成可编程、可复现、可审计的工程对象。

如果说前几天的趋势是"安全从 prompt 下沉到 runtime"，那今天就是再下一步——runtime 本身也开始被重新定义。可审计、可验证、可重放，这三个词，会是接下来一段时间 Agent 系统设计的新准绳。

如果你现在正在做 Agent，今天可以问自己三个问题：你的编排逻辑，未来能不能让模型自己写？你的训练或评测环境，能不能脱网复现？你接的每一个外部工具，进来和出去的数据，有没有被当作攻击面来看？

想清楚这三个问题，今天的内容就没白听。

我们明天见。
